# 校园通知、个人待办与学习资料助手

## 使用流程

点击课程资料名称或“查看详情”可查看上传资料和 AI 联网资料的正文；正文分页展示，导入中的 Markdown、TXT 文件提供文字预览。问答会检查资料是否足以回答当前问题，即使模型错误地将资料不足的回复标为可回答，也会转入联网补充流程并展示参考提示与网页来源。

课程资料列表新增“搜索课程资料”：可指定主题及1到10份的上限，默认3份。提交后在后台联网检索并生成带网页来源的 Markdown 学习资料，自动存入当前个人课程并导入索引；页面显示排队、生成、导入和完成状态，刷新后保留进度。每批最多整理3份并逐批存入，同一课程有进行中的批次时禁止重复提交。完成后可再次生成，跳过已有同名资料。AI 联网整理内容仅供参考，不是原始讲义。导入失败可在资料列表中重试。

联网回答的网页来源默认收起，点击“展开网页来源”查看链接，再次点击可收起。学习记录按“回复、摘要、练习题”分类分页，仅显示标题和时间；点击标题在侧栏查看完整内容、引用和参考提示。

刷新页面后，侧栏新增“校园通知”“个人待办”“学习资料助手”。学生和管理员都有个人空间；管理员额外拥有通知编辑和发布操作。

**通知与待办**

1. 管理员进入校园通知，新建草稿，粘贴已核验的官方正文和 `hut.edu.cn` 或其子域的原文链接。当前不自动请求链接、不定时采集网站。
2. 可点击“AI 提取摘要与办理信息”。提取结果只是编辑建议，核对标题、类别、对象、地点和时间后保存草稿，再确认发布。没有明确完整截止时刻时留空；页面显示“未明确”。
3. 用户勾选教学、学工、招聘或生活类别。只接收订阅后新发布的通知，消息中心可直接打开原通知。可收藏通知并筛选收藏列表。
4. 打开通知，点击“加入个人待办”，检查并编辑标题、备注、截止与提醒时间后保存。同一用户从同一通知重复添加会返回原待办。
5. 个人待办支持新建、修改、完成、筛选和删除。时间按北京时间填写，数据库保存有时区时间。提醒时间需在未来且不晚于截止时间。
6. Scheduler 每30秒扫描到期事项，Worker执行提醒，消息中心每5秒取新消息。每个待办只提醒一次，已完成待办不提醒；离线用户再次登录后可从消息中心查看。已经提醒过的待办不重新安排提醒，后续提醒可新建待办。
7. 已发布通知不能直接修改，避免学生收藏和待办引用静默改变；修改时撤回并创建修订通知。撤回后学生不能查看，已创建待办保留个人记录并标注来源已撤回，相关提醒暂停。

**个人学习**

资料回答和复习提纲（包括历史记录详情）按Markdown阅读排版显示：标题、重点、列表、引用提示、表格和代码块使用统一样式，不直接展示`#`、`**`和表格分隔标记。整段被`markdown/md/text`代码围栏包裹的回复会展开正文，真正的代码符号保留；表格及代码块在窄屏内部横向滚动。2026-10-12：前端生产构建、桌面/窄屏排版测试2项及一键提纲回归2项通过，截图核验完成。

新生成的练习固定10道（目标5道判断题、5道简答题），每题10分、总分100分；旧练习保留原题数并兼容提交。生成使用8192 token输出预算，简答题每批最多3道进行评分点制定与独立复核，汇总全部题目得分及各批复习建议，避免十题输出截断。

评分后的“复习建议”卡片提供“一键生成复习提纲”：自动关闭学习记录详情、切换到提纲任务、将建议填写到主题框并立即生成。建议输入保留，可继续编辑；生成失败时也保留输入供重试。主题最多4000字，过长建议按输入限制截取。

2026-10-12验收：完整后端回归120项、Ruff及前端Docker生产构建通过；一键提纲浏览器验证2项通过（成功生成和失败保留输入）。公开Java测试资料的真实模型生成10题（5判断、5简答）、十题批改汇总及按建议生成提纲通过，不读取用户现有记录。

练习题支持判断题和简答题。每题填写答案后，在题目上方点击“提交答案”，AI 会逐题显示对错或得分（每题10分）、得分理由和知识点，并自动展开参考答案、讲解及引用；底部根据本次答题情况提供复习建议。未完成所有题目时不能提交。旁边的“显示答案”可一键查看全部参考答案，无需提交或调用评分模型。答案和最近一次评分随学习记录保存；修改答案后需重新提交，评分失败时保留本次输入以便重试。旧练习作为简答题兼容此流程。AI评分仅供学习参考，模拟模式只对比文本，不作语义判断。

1. 新建课程，上传 MD、TXT、DOCX 或文本型 PDF。沿用20MB、PDF100页限制和原有后台导入管线；不支持扫描件OCR或PPTX。
2. 等待资料“已发布”，即可资料问答、生成复习提纲或练习。导入状态、失败原因、重试和资料更新可在课程表格查看。更新失败时仍使用旧版本。
3. 问答可连续追问，模型最多使用该课程最近四次问答。提纲/练习可填写主题，使用混合检索选择片段；留空时按资料轮流选取正文片段，最多20个且受上下文长度限制。结果只覆盖选取内容，不保证整门课程覆盖率。
4. 结果展示模拟/真实模式与可打开的来源片段。练习可先填写自己的理解，再查看参考答案、讲解和对应引用，也可提交答案获取逐题评分和复习建议；AI评分仅供学习参考。
5. 学习记录保存到课程，刷新后仍可查看。删除资料会退出检索，引用它的历史生成结果隐藏正文与练习并提示重新生成。更新资料后旧版本引用仍供本人核对。
6. 演示笔记在 `samples/study/database-notes.md`，内容为自行编写，非学校课程文件或考试范围。

## 权限与实现

- 数据迁移：`0005_campus_learning` 增加通知、订阅、收藏、待办、课程与学习记录表，并扩展文档归属与消息目标。已有账号、知识库、会话、工单与消息保留。
- 学习资料绑定 `owner_id` 和 `course_id`，仅本人读取。其他学生与管理员均不能访问个人课程、资料、历史和来源。校园检索与管理员知识库列表排除所有个人资料，BM25缓存按用户/课程/模型/知识库代际隔离。
- 复用 Celery 文档导入、BGE-M3 1024维索引、向量+BM25+RRF和模型HTTP接口。真实模型使用当前后端配置，个人资料的选中片段会发送给配置的聊天供应商处理；“仅本人可见”指本项目用户访问权限，不代表模型在本地运行。
- 通知发布和订阅推送同事务提交，重复发布不重复通知。待办提醒使用行锁、提醒状态和用户/事件唯一约束，重复Worker执行不重复推送。
- 所有生成输出经过结构与引用编号校验；生成后再次校验资料是否删除或换版。模型错误返回失败信息，不保存无效学习结果。请求追踪记录 `notice_extract`、`study_question`、`study_outline`、`study_practice`。
- 无学校认证、个人教务数据或审批系统接入。通知摘要由本项目管理员整理，应以官方原文为准。

## 新接口

均使用 `/api/v1` 和原有登录Cookie；列表默认每页20，最大100，权限错误使用原统一错误结构。

| 接口 | 用途 |
| --- | --- |
| `GET/PUT /subscriptions` | 当前用户类别订阅 |
| `GET/POST /announcements` | 通知分页查询/管理员创建草稿 |
| `POST /announcements/extract` | 管理员提取待核对的AI建议 |
| `GET/PUT /announcements/{id}` | 查看通知/修改草稿 |
| `POST /announcements/{id}/publish`、`/withdraw` | 管理员发布/撤回 |
| `PUT /announcements/{id}/saved` | 当前用户收藏/取消收藏 |
| `GET/POST /todos`、`GET/PUT/DELETE /todos/{id}` | 当前用户个人待办 |
| `GET/POST /courses` | 当前用户课程列表/创建 |
| `GET/POST /courses/{id}/documents` | 个人资料分页列表/上传 |
| `POST /courses/{course_id}/documents/{id}/versions`、`/retry` | 更新/重试个人资料 |
| `DELETE /courses/{course_id}/documents/{id}` | 撤销个人资料 |
| `GET/POST /courses/{id}/study` | 学习记录/生成问答、提纲、练习 |
| `POST /courses/{id}/study/{run_id}/submit` | 完成练习后统一提交答案并保存AI评分与复习建议 |

消息接口新增可空的 `announcement_id`、`todo_id`；`ticket_id`对新消息可为空，原工单消息保持原行为。

# 资料不足时联网补充

资料问答优先使用当前课程资料；没有可用片段或资料不足以支持回答时，使用当前 DeepSeek 服务的原生 `web_search_20250305` 工具联网搜索。网页来源仅从搜索工具实际返回的 HTTP(S) 链接提取，不采用模型编造的链接。

补充回答单独保存 `answer_kind=web` 与 `web_sources`，界面及学习历史显示“本回答未来自课程知识库，仅供参考”和可点击的网页来源。搜索只发送当前问题，不把上传资料片段发送给搜索工具。提纲和练习仍仅依据课程资料。搜索未返回完整答案或有效来源时提示重试，不保存为成功回答。
