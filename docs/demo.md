# 演示脚本

所有资料为自行编写的模拟校园内容；不要导入真实校园密码或个人数据。

1. 启动并初始化两个账号。使用管理员登录“知识库管理”，上传 `samples/vpn-809.md`，观察排队、解析、分块、向量化和已发布状态；打开资料查看版本与分块。
2. 学生登录，提问“VPN 错误 809 怎么处理？”。页头和回答标注模拟模式；打开引用，核对文档标题、版本和来源正文。
3. 再问“按步骤操作后还是失败，宿舍电脑仍无法连接”。点击“未解决？创建工单”，编辑标题、描述和地点，确认提交。会话转换为工单模式。
4. 管理员进入工单工作台，标记为处理中，回复“请补充系统版本和错误截图描述”，标记待补充。
5. 学生回复补充信息；管理员回复处理结果并标记已解决。学生可重新打开，或确认解决并关闭；关闭后不再显示回复输入。
6. 管理员上传 `samples/admin-internal.md` 为“仅管理员可见”。学生搜索 `ADMIN-ONLY-ORCHID` 应无法获得内部来源，管理员可检索。将公开资料改为管理员可见，学生的旧引用不再可访问。
7. 给已发布资料上传内容损坏的 DOCX 新版本，观察明确失败原因和旧版本仍可用；失败版本重试不会重复创建分块。上传空文件直接返回输入错误。
8. 停止并重新启动 Compose，登录后文档、历史会话、工单与文件仍存在。自动浏览器流程运行后，还可以执行 `scripts/check_persistence.py`。

简历可描述已实现的 RAG 工程、权限过滤、文档版本发布、SSE、幂等工单和测试。不声称未经测量的 AI 准确率、延迟、成本或校园生产规模。
